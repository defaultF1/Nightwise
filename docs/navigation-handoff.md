# Navigation handoff repair - 16 September 2026

Latest local UI revision: Android now filters the navigation dropdown to installed supported apps and offers a browser fallback when none are available. See [the control and route revision](local-ui-route-review-2026-09-16.md). The destination/mode/waypoint rules below remain in effect.

The destination-only Android `geo:` chooser dropped the selected origin, mode and route guides. The navigation sheet now selects Google Maps or Mappls, then passes the complete provider-specific directions link through `MapsHandoff.open`.

- Google Maps: origin, destination and driving/walking/two-wheeler mode. The fastest route (identified by ID, regardless of its display label) has no extra stops. Alternatives have up to three ordered route points.
- Mappls: origin, up to three ordered route points and destination, with driving/walking/biking mode and `region=ind`. Route points are also included for the fastest route. Native Android uses the `mapmyindia://navigation` format generated by Mappls' own site, with an unchanged directions-URL fallback if the installed app cannot handle that link.
- Stale, invalid, short or illustrative paths do not produce route points. Neither app is forced to follow the entire original polyline: roads between the points can be recalculated.
- The Car/Bike/Walk control is an in-app dropdown with icons, theme colours, keyboard support, outside-click dismissal and Android Back dismissal. Car remains the default.

## Provider evidence

Checked on 16 September 2026:

- [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started): directions endpoints, travel modes and ordered waypoints; mobile browser fallback supports up to three waypoints.
- [Mappls directions links](https://developer.mappls.com/mappls-apps/mappls-app/): ordered origin/via/destination places.
- [Mappls public website JavaScript](https://www.mappls.com/js/?392.js): its route-sharing code constructs `deepMode` and `shareLink` with `places`, `mode` and `region`. Its native link uses `mapmyindia://navigation` with the same ordered places. This is implementation evidence beyond the abbreviated public directions documentation, not a guarantee for every installed Mappls version.

## Scope and verification

The embedded MapLibre map, Geoapify/OpenStreetMap providers, data, scoring, API keys and backend configuration are unchanged. No extra data API calls are needed for this handoff. Work is local on `codex/restore-navigation-directions`; no hosting or GitHub publication is included.

Automated coverage checks walking endpoints and mode, Google fastest without stops, alternatives with stops, Mappls fastest with points, stale-path handling and native bridge arguments. Browser checks cover the route-to-handoff flow and the custom dropdown in dark/light/blue at 360 px, with mocked comparison responses. Installed-app reception still requires a phone check; the browser tests do not launch Google Maps or Mappls on Android.
